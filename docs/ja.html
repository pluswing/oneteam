単独開発者のためのローカルLoop Engineering

OneTeam

ユーザーはいつも通りIssueを書く。OneTeamはその裏側でstanding objectiveを回し、 要件定義、実装、レビュー、QA、verification gate、judgeの判定、Evidence、Memoryを Pull Requestまで運びます。最後のMerge判断はユーザーに残します。

ダウンロード 画面を見る pluswing/oneteam

Issue-firstで使える、ローカルLoop Engineering

OneTeamは手元のGitリポジトリを登録して使います。インポートしたリポジトリrootの `.oneteam` 以下にDB、skills、memoryを置くため、プロジェクトを切り替えると コードとAI開発状態をまとめて切り替えられます。

Issue

Loop設定ではなくIssueを書く

ユーザーはIssueに要望を書く。Requirements AgentがGoal Contract、Evidence、リスク、引き渡し条件を推定します。

Objective

standing objectiveで束ねる

1つのObjective RunがIssueとPull Requestをまたぎ、実装、レビュー、修正、QA、Verifierまで追跡します。

Agent Job

Evidenceで完了を止める

Verification gateが、コマンド結果、変更ファイル、停止理由、VerifierのEvidenceなしの完了を止めます。

Scheduler

裏側で作業候補を発見

内部SchedulerがOpen IssueにObjectiveを補完し、不足コマンドなどのリポジトリ問題をTriageへ送ります。

Judge

作る役と判定役を分ける

Verifier Jobをjudgeとして記録し、AI provider、missing evidence、notes、ready-to-merge状態を残します。

Comments

表現力の高いAgentコメント

AgentはMarkdownまたはサニタイズ済みHTMLで、表、callout、構造化レポートをコメントできます。

Issueから検証済みPull Requestへ

ユーザー体験はシンプルです。Issueを作り、必要なら質問に答え、Pull Requestを確認する。 その裏側でLoop control planeが動きます。

  1. 1. リポジトリを登録 Gitリポジトリをインポートし、Codex、Claude Code、LM StudioからAI providerを選びます。
  2. 2. Issueを作成 作りたい内容を書くと、OneTeamがstanding objectiveを作り、必要なEvidenceを定義します。
  3. 3. Agentが実行しJudgeが判定 実装、レビュー、修正、QA、Verifierがworktreeで動き、EvidenceとObjective状態を更新します。
  4. 4. 判断してMerge Verifierがready-to-mergeにしたら、Objective summaryとEvidenceを確認してユーザーがMergeします。

主要画面

アプリをダウンロード

OneTeamはmacOS向けアプリとしてGitHub Releasesから配布します。最新のDMGをダウンロードし、 OneTeam.appを起動して、初回起動時にCodex、Claude Code、LM Studioのいずれかを選択してください。 ローカルでのビルドは不要です。

  1. 最新リリースをダウンロードします。
  2. DMGを開き、OneTeam.appを起動します。
  3. リポジトリを選択または追加し、そのリポジトリ配下にDB、skills、memoryを保存します。
  4. Issueを作成すると、Objectiveに紐づくAI開発ループが裏側で進みます。
